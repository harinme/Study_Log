# 데이터베이스 개념

## 데이터 베이스

> 특정 조직의 업무에 필요한 상호 관련된 **데이터들의 집합**

- 여러 사용자와 응용 프로그램이 공유하고 통합적으로 관리할 수 있도록 구성된 데이터 모임

### (1) 데이터와 정보

|       구분        | 설명                                                |
| :---------------: | :-------------------------------------------------- |
|   데이터(Data)    | 관찰이나 측정을 통해 수집한 사실이나 값             |
| 정보(Infornation) | 데이터를 처리하여 의사결정에 유용하게 정리한 결과물 |

### (2) 데이터베이스의 정의

|              정의              | 설명                                            |
| :----------------------------: | :---------------------------------------------- |
| 통합 데이터 (Integrated Data)  | 중복을 최소화하여 통합된 데이터 모임            |
|   저장 데이터 (Stored Data)    | 컴퓨터가 접근할 수 있는 매체에 저장된 데이터    |
| 운영 데이터 (Operational Data) | 조직의 목적을 달성하기 위해 필수적인 데이터     |
|   공유 데이터 (Shared Data)    | 여러 응용 프로그램들이 공동으로 사용하는 데이터 |

## 데이터베이스 스키마(Schema)

### (1) 스키마의 정의 _\*[20년 3회]_

- 데이터베이스의 구조, 제약조건, 속성, 개체(Entity), 관계(Relation)를 포함한 전반적인 명세를 기술한 것
- 개체는 여러 속성(Attribute)의 집합으로 구성되며, 개체들 간에는 관계(Relation)가 존재
- 스키마에 명시된 정보는 데이터사전(Data Dictionary)에 저장

### (2) 3계층 스키마 _\*[23년 1회]_

> 외부: 사용자 뷰 / 개념: 전체적인 뷰 / 내부: 저장 스키마

|              |                  |              |
| :----------: | :--------------: | :----------: |
| 외부 스키마1 |   외부 스키마2   | 외부 스키마3 |
|      \       |        │         |      /       |
|              | **개념 스키마**  |              |
|              |        │         |              |
|              | **내부 스키마**  |              |
|              |        │         |              |
|              | **데이터베이스** |              |

1. 외부 스키마(External Schema) - 사용자 뷰
   - 사용자나 응용 프로그램의 관점에서 데이터베이스의 논리적 구조를 정의함
   - 서브스키마(Sub Schema)라고도 불리며, 하나의 데이터베이스에 여러 개의 외부 스키마가 존재 가능
   - 여러 응용 프로그램이나 사용자가 하나의 외부 스키마를 공유하여 사용할 수 있다.
   - 데이터베이스 접근 시 SQL과 같은 질의어나 C, Java 등의 프로그래밍 언어를 사용할 수 있다.

2. 개념 스키마(Conceptual Schema) - 전체적인 뷰
   - 데이터 베이스의 전체적인 논리적 구조를 나타냄
   - 일반적으로 하나의 데이터베이스에는 하나의 개념 스키마만 존재
   - '스키마'라는 용어는 주로 개념 스키마를 의미
   - 데이터 접근 권한, 보안 정책, 무결설 규칙 등의 명세를 포함

3. 내부 스키마(Internal Schema) - 저장 스키마
   - 물리적 저장 장치의 관점에서 데이터베이스의 구조를 정의
   - 실제로 데이터가 저장장치에 어떻게 배열되고 저장되는지 레코드의 물리적 구조, 표현방식, 순서 등을 명세

### (3) 데이터 독립성

1. 논리적 독립성
   - 응용 프로그램에 영향을 주지 않고 데이터베이스의 논리적 구성을 변경할 수 있는 능력
   - 개념 스키마가 변경되어도 외부 스키마에는 영향을 주지 않도록 지원함

2. 물리적 독립성
   - 응용 프로그램이나 데이터베이스의 논리적 구조에 영향을 주지 않고 데이터의 물리적 구조를 변경할 수 있는 능력
   - 내부 스키마가 변경되어도 외부 및 개념 스키마가 영향을 받지 않도록 지원함

## 데이터베이스 관리 시스템(DataBase Management System)

### (1) DBMS의 정의

- 데이터베이스를 효과적으로 관리하고 조작하기 위한 전용 소프트웨어임

### (2) DBMS의 기능

|    기능     | 설명                                                                                     |
| :---------: | :--------------------------------------------------------------------------------------- |
| 데이터 정의 | 데이터의 형식, 구조 및 제약 조건을 정의한다.                                             |
| 데이터 조작 | 데이터 검색, 갱신 및 보고서 생성을 위한 질의 수행을 제공한다.                            |
| 데이터 제어 | 데이터 무결성, 보안 및 동시성 제어 기능을 포함한다.                                      |
| 데이터 공유 | 여러 사용자나 응용 프로그램이 동시에 데이터베이스에 접근할 수 있게 한다.                 |
| 데이터 보호 | 불법적이거나 권한이 없는 접근, 시스템 장애로부터 데이터를 보호한다.                      |
| 데이터 구축 | 데이터를 DBMS가 관리하는 저장 장치에 저장하는 기능이다.                                  |
|  유지보수   | 시간이 흐름에 따른 요구사항의 변화를 반영하여 데이터를 수정하거나 업데이트하는 기능이다. |

### (3) DBMS의 종류

1. 계층형(Hierarchical DataBase)
   - 데이터를 트리 구조로 표현하며, 세그먼트 단위로 관리
   - 구조가 단순하고 검색이 빠르지만, 다대다 관계를 처리하지 못하며 구조 변경이 어려움

2. 네트워크형(Network DataBase)
   - 계층형 모델의 단점을 보완하여 다대다 관계를 표현할 수 있는 망형 구조를 사용
   - 구조가 복잡하여 유지보가 어려움
   - CODASYL이 제안하여 CODASYL DBTGA 모델로도 불림

3. 관계형(Relational DataBase)
   - 키(Key)와 값(Value)으로 이루어진 데이터를 행과 열로 구성된 테이블 구조로 표현
   - SQL(Structured Query Language)을 사용하여 데이터를 처리

4. 객체지향형(Object-Orient DataBase)
   - 객체지향 프로그래밍 개념에 기반하여 개발된 데이터베이스 모델
   - 정보를 객체 형태로 표현하며, 클래스, 상속 등의 객체지향 프로그래밍 개념을 사용할 수 있음
   - 비정형 데이터를 데이터베이스로 관리하기 위한 목적으로 설계됨

5. 객체관계형(Object-Relational DataBase)
   - 관계형 데이터베이스에 객체지향 개념을 결합한 모델

6. NoSQL
   - Not Only SQL의 약자로, 다양한 데이터 모델을 지원하며 **비정형 데이터 처리에 적합**
   - 스키마 변경이 불가능하고 데이터 오류 감지가 어려움

7. NewSQL
   - RDBMS와 NoSQL의 장점을 결합하여 확장성과 트랜잭션을 동시에 지원하는 데이터베이스 모델
